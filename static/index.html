The problem it solves

Fraud isn't a row in a spreadsheet. It's a network — and investigators are still fighting it with tables.

Billions lost to mule networks

Organized rings move dirty money through chains of "mule" accounts, keeping each transfer just under reporting thresholds. The pattern is invisible in tabular reports.

6 hours per account

A human analyst tracing one suspect through spreadsheets takes half a workday. By the time the trail is mapped, the money has already left the system.

Dashboards only watch

Existing tools raise alerts and build charts — but nobody acts. The investigator still has to manually freeze accounts across disconnected systems.

How it works

Four steps. One graph. Zero black boxes — every action displays the exact query the agent ran.

1

Trace the money

Enter a suspect account. The agent follows transfers N hops deep — a traversal SQL can't express without painful recursive queries.

MATCH p=(a)-[:TRANSFERRED*1..4]→(b)
2

Hunt the ring

Mule networks reuse devices. The agent finds 4+ accounts on one device sharing IPs — the classic fraud-ring fingerprint.

MATCH (d:Device)←[:USES_DEVICE]-(a)
3

Find the hub

PageRank over money-flow edges surfaces the laundering kingpin — the account everything flows through. No labels needed.

CALL algo.pageRank() YIELD node
4

Execute freeze

The agent doesn't just report — it acts. Accounts freeze, and a case file is written back into the graph as institutional memory.

SET a.frozen=true CREATE (:Case)
